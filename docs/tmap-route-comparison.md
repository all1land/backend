# 자체 통합 경로와 TMAP 비교 검증

## 목적
같은 출발지, 출발 측 POI, 주차장, 목적지 조건에서 자체 경로와 TMAP 결과를 비교한다.

## 기존 구현 재사용
- 통합 경로: 이슈 #16, PR #19
- TMAP 연결: 이슈 #9의 기존 구현 재사용
- TMAP 원본 커밋: f3e5bbb3ca6326faeee29ecb3e13b0299a326ae5
- DB 마이그레이션 변경 없음

## 실행 조건
- Java 21
- V1~V9 마이그레이션이 적용된 PostgreSQL/pgRouting DB
- DB_URL, DB_USERNAME, DB_PASSWORD 환경변수 설정
- 실제 TMAP_APP_KEY 환경변수 설정
- API 키는 코드나 Git에 저장하지 않는다.

## 실행 방법
프로젝트 폴더의 PowerShell 터미널에서 서버를 실행한다.

    .\gradlew.bat bootRun --args="--server.port=8082"

서버 실행 후 별도 PowerShell 터미널에서 비교 스크립트를 실행한다.

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\compare-tmap-route.ps1"

## 확인한 사항
- 자체 통합 경로와 TMAP 세 구간의 실제 API 호출 성공
- 자체 구간별 거리·시간 합계와 전체 합계 일치
- 원본 요청과 응답을 JSON으로 저장

## 해석 및 제한사항
- 자체 차량 경로에는 양 끝 도보 접근 구간이 포함된다.
- TMAP은 도로 접근 구간 처리 방식이 다를 수 있다.
- 자체 차량 시간은 제한속도 기반으로 교통 상황과 신호 대기 등을 반영하지 않는다.
- 수치 차이를 정확도 오차나 어느 경로가 우수하다는 근거로 해석하지 않는다.
- TMAP 결과는 실행 시점 등에 따라 달라질 수 있다.
- 현재는 한 가지 고정 시나리오를 검증한 상태이다.
